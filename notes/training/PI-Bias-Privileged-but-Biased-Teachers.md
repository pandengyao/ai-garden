# Privileged, but Biased: How PI-Conditioned Teachers Break Self-Distillation（有特权，但有偏见：看过答案的老师如何让自蒸馏失效）

## 一句话版本

自蒸馏（Self-Distillation，SD）是这样一种训练方法：同一个模型多看一份特权信息（Privileged Information，PI，比如参考答案），给只看题目的自己当老师，沿着学生自己写的解答逐个 token 纠正它。它不需要奖励，也不需要更大的老师模型，在简单问答上有效。这篇论文不提新方法，是一项诊断研究：作者把它原封不动搬到难的问答、数学、编程和多轮工具调用任务上，看只用它训练时模型到底学到了什么，再一环一环找失败的原因。原因是看过一份参考答案的老师，只会把学生往"那一份答案的写法"上拉，"做对"这件事并不在它的目标里。

主要发现：用 Qwen3-8B 在这四类难任务上只做自蒸馏，训练损失一路下降，成绩却不涨，多数还在下降。按 SDPO 的训练配方（一种已发表的自蒸馏做法）训练时，掉得最多的是 think 模式（先长篇思考再作答）的多轮工具调用，平均掉 3.51 个百分点（下文简称"分"），其中一项掉 7.0 分；换成另一种做法 OPSD 的配方，think 模式的数学平均掉 4.28 分。问题从老师开始：数学题上，老师对它看过的那份答案的 PI 偏差分数（看了答案后，模型续写这段文字的意愿提高了多少）是 0.52，换成同一道题的另一份正确答案，测过的三个领域都只有 0.02 左右或更低。

## 1. 先认识几个词

| 词 | 大白话 |
| --- | --- |
| 自蒸馏（SD） | 同一个模型既当学生又当老师，老师多看一份特权信息，逐个 token 告诉学生该怎么写 |
| 特权信息（PI） | 只在训练时给老师看的额外信息，比如参考答案、提示、单元测试的报错；测试时没有 |
| RLVR / GRPO | 用程序判对错当奖励的强化学习；GRPO 是其中一种常用算法 |
| token | 模型读写文字的最小单位，大致是一个词或词的一部分 |
| 解答（rollout） | 模型针对一道题自己生成的一份完整回答 |
| 损失（loss） | 训练时要压低的那个数；在自蒸馏里，就是学生和老师在每个位置上的分布差距 |
| KL / JSD | 衡量两个概率分布差多少的指标（这类指标统称散度），越大差得越多；JSD 是 KL 的对称版本 |
| 熵（entropy） | 模型每一步有多拿不准，越高越犹豫 |
| think / instruct 模式 | Qwen3 的两种用法：think 先长篇思考再作答，instruct 直接作答 |
| EMA 老师 | 老师的参数每一步只朝学生的最新参数挪一小步，相当于"慢半拍的学生" |
| 迁移测试 | 没拿来训练的其他数据集，用来看学到的本事能不能带到别处 |
| 犹豫词 | wait、maybe、perhaps 这类表示拿不准的词，论文叫 uncertainty marker |
| on-path / off-path | 解答里贴着参考答案路线的位置 / 偏离参考答案路线的位置 |
| PI 偏差分数（PI Bias Score） | 本文提出的指标：看了 PI 后，模型续写某段文字的意愿提高了多少 |

## 2. 它想解决什么问题

提升大模型推理能力的主流做法是 RLVR（带可验证奖励的强化学习，代表算法是 GRPO，出自 Shao 等 2024 年的 DeepSeekMath 论文，[arXiv 2402.03300](https://arxiv.org/abs/2402.03300)）：模型做一道题，程序检查最终答案，对了给 1 分，错了给 0 分，再用这个分数训练。论文总结了它的三个缺点：

- **太粗**：几千个 token 的解答只拿到一个分数，每个 token 分到的功劳都一样。
- **太稀**：难题上模型可能一次都做不对；一组解答得分全一样（全对或全错）时，组内没有差别，也就没有学习信号。
- **太贵**：每次更新都要验证器打分，还要采样很多份解答。

自蒸馏想要更密的信号，又不想额外请一个更大的老师模型。做法是：

1. **学生**（模型本身）只看题目，自己写一份解答。
2. **老师**还是同一个模型（或它参数的慢速副本），但输入里多了一份特权信息，比如参考答案、提示、单元测试的报错。特权信息只在训练时有，测试时没有。
3. 沿着学生写的每个 token，老师给出"换成看着答案的我，下一个 token 会怎么写"的概率分布。
4. 训练让学生每个位置的分布都向老师靠拢。

打个比方（类比是我加的，不是论文原文）：学生自己做题，旁边坐着一个"翻着答案册的自己"，学生每写一个字，它都给出"按答案册这里该怎么写"。每个 token 都有反馈，不需要奖励，也不需要更大的模型。

几条路线放在一起看（这张表是我根据论文第 1、2 节整理的）：

| 路线 | 做法 | 问题 |
| --- | --- | --- |
| RLVR（如 GRPO） | 程序判对错给分，按分数训练 | 信号太粗、太稀、太贵 |
| 普通蒸馏 | 另一个更大的老师模型逐 token 给出分布，学生去贴近 | 信号密，但得另外有一个更大的老师 |
| 自蒸馏 | 看了特权信息的自己当老师，逐 token 纠正学生 | 不要奖励，也不要更大的老师；但正面结果几乎都来自简单任务 |

**选读：自蒸馏的损失（论文式 (1)）。** 不看也不影响理解。

```math
\mathcal{L}_{\text{SD}}(\theta)=\mathbb{E}_{(x,r)}\,\mathbb{E}_{\hat y\sim \mathrm{sg}(p_S)}\left[\frac{1}{|\hat y|}\sum_{t=1}^{|\hat y|} D\Big(\mathrm{sg}\big(p_T(\cdot\mid x,r,\hat y_{<t})\big)\;\Big\|\;p_S(\cdot\mid x,\hat y_{<t})\Big)\right]
```

- $`x`$ 是题目，$`r`$ 是 PI，$`\hat y`$ 是学生自己写的解答。
- $`p_T`$ 是看了 PI 的老师在第 $`t`$ 个位置给出的下一个 token 分布，$`p_S`$ 是学生的分布。
- $`D`$ 衡量两个分布差多少，$`\mathrm{sg}`$ 表示老师这一侧不回传梯度，只更新学生。

整个式子的意思是"沿着学生写的每个 token，让学生向老师看齐"，里面没有任何奖励项。

两种代表做法（下文的"SDPO 配方"和"OPSD 配方"就是指它们的训练设置）：

- **SDPO**（Hübotter 等，2026，[arXiv 2601.20802](https://arxiv.org/abs/2601.20802)）：老师看的是反馈，可以是之前做对的一份解答，也可以是单元测试报错这类环境输出。原论文报告在 SciKnowEval、ToolAlpaca、LiveCodeBench 上用少几倍的算力达到或超过 GRPO。
- **OPSD**（Zhao 等，2026，[arXiv 2601.18734](https://arxiv.org/abs/2601.18734)）：老师看的是参考答案，参数固定为初始模型。原论文报告在 AIME、HMMT 上超过 GRPO 和离线蒸馏。

作者认为这些正面结果几乎都来自窄的、低难度的设置，比如短的科学知识选择题。另一批工作把 SD 当作强化学习里权重很小的辅助项，主力仍是奖励。"在难任务上只用 SD"没有人测过。

论文要回答的问题是：**在难任务上，不加任何奖励、只用 SD 训练，模型优化的到底是"做对"，还是一个只在简单题上恰好和"做对"相关的替代指标？**

## 3. 实验结果

### 3.1 实验怎么设计的

**先在原来的简单设置里复现。** 作者用 SDPO 的官方代码和它报告的超参数，在 SciKnowEval（科学知识问答）上训练 Qwen3-8B，PI 用整份答案，得到和原论文一样的趋势（论文图 1）：生物、物理两科损失下降、验证集准确率上升（生物约 0.31 → 约 0.5，物理约 0.65 → 约 0.8，读图估计），回答也变短了。作者认为这说明实现没问题，后面所有实验都在这套代码上做。

**再原封不动搬到四个难领域**（论文第 4 节，附录表 6）：

| 领域 | 训练数据 | 领域内测试 | 迁移测试（没训练过的数据集） |
| --- | --- | --- | --- |
| 通用问答 | MMLU-Pro（2000 题） | MMLU-Pro | GPQA-Diamond；SciKnowEval 的生物、化学、材料、物理 |
| 数学 | DAPO-Math（2000 题） | DAPO-Math | AIME24、AIME25、OlympiadBench |
| 编程 | CodeForces（2000 题） | CodeForces | MBPP+、HumanEval+、CodeElo、LiveCodeBench v6 |
| 多轮工具调用 | BFCL v3 多轮（100 个任务） | BFCL v3 多轮 | BFCL v4 多轮：base、缺函数、缺参数、长上下文 |

其他设置：

- **模型**：主力是 Qwen3-8B，think 和 instruct 两种模式都测；另在通用问答上加测 Qwen3-32B。
- **PI**：默认是一整份参考答案。这份答案其实是模型自己之前某次做对的解答，去掉了思考过程。另外还测了两种更"弱"的 PI：1～2 句话的提示（hint），以及按题目类别写的、约 500 token 的技巧卡（skill，讲通用方法、常用公式和常见坑，不透露答案）。
- **训练目标**：只有式 (1)，损失里没有奖励，也没有验证器。$`D`$ 用对称的 JSD，和 SDPO 一致。
- **稳定训练的两个措施**：一是逐 token 截断老师和学生分布的差距，因为不截断时，MMLU-Pro 上损失最大的一半 token 占了 98.5% 的损失，少数 token 会主导梯度；二是让老师参数很慢地跟随学生（EMA，α=0.001，SDPO 原来用 0.01）。
- **配方**：主实验用 SDPO 配方，另在通用问答和数学上用 OPSD 配方重做一遍。
- **对照和指标**：每个训练后的模型只和它自己训练前的版本比，没有跑别的训练方法。数学和问答看准确率，编程看通过的测试用例比例，工具调用看 BFCL 的成功率；每个分数是每题 4 次采样的平均。
- **其他超参数和算力**：学习率 1e-5（编程和工具调用用 1e-6），每批 32 道题，训练 3 轮；所有实验都在一台 8 卡 NVIDIA B200 的机器上跑（附录 B）。

### 3.2 训练时：损失在降，验证集不涨

作者说，四个领域、两种模式下，训练曲线几乎是同一个样子（论文图 2 画了 Qwen3-8B 在四个领域上的曲线）：

| 指标 | 怎么变 | 说明 |
| --- | --- | --- |
| 训练损失 | 稳定下降 | 按损失衡量，学生越来越接近老师 |
| 验证集准确率 | 持平或下降 | "像老师"没有变成"会做题" |
| 学生的熵 | 多数领域上升 | 熵衡量模型每一步有多拿不准。正常变强的模型应该更笃定，这里反而更犹豫 |
| 回答长度 | 多数领域变短，数学从约 1 万降到约 7 千 token（读图估计；工具调用是例外，见第 6 节） | 短问答里变短是好事；推理题里，这和"下结论前的试错变少了"对得上 |

作者的看法是：单看任何一条都能找到无害的解释，四条一起出现就说明是系统性问题。唯一的例外是工具调用的 instruct 模式，验证集有小幅提升，原因见 3.3 节。

### 3.3 SDPO 配方的成绩：think 模式四个领域全降

论文表 1（SDPO 配方，各领域平均分，%；训练前 → 训练后，括号里是变化，单位是分）：

| 领域 | think 模式 | instruct 模式 |
| --- | --- | --- |
| 通用问答 | 60.93 → 59.37（−1.56） | 52.62 → 51.05（−1.57） |
| 数学 | 63.38 → 63.10（−0.28） | 34.82 → 33.02（−1.80） |
| 编程 | 47.62 → 47.32（−0.30） | 40.80 → 41.74（+0.94） |
| 多轮工具调用 | 51.36 → 47.85（−3.51） | 28.90 → 33.58（+4.68） |

怎么读这张表：

- **think 模式**：四个领域全部下降，工具调用掉得最多，其中"缺函数"子项掉了 7 分。
- **两个正数**：都在 instruct 模式，作者认为都不算真正的提升。工具调用 +4.68，训练集只有 100 个任务、回答很短（平均约 300 token），第 4 节的因果链发挥不出来；编程 +0.94 主要靠 MBPP+ 一项 +12.6，其他四项都在降。

### 3.4 换成 OPSD 配方，结果一样

用 OPSD 的配方（每步只采一份解答、固定的参考答案、老师固定为初始模型）在通用问答和数学上重做。论文表 2（各领域平均分的变化，分）：

| 领域 | think 模式 | instruct 模式 |
| --- | --- | --- |
| 通用问答 | −1.96 | −0.65 |
| 数学 | −4.28 | −0.44 |

20 个"测试集 × 模式"的格子里有 18 个没有提升。两种配方在怎么算差距（散度的方向）、老师参数怎么更新、每步采几份解答和怎么截断上都不同，结果却一样。作者据此认为，问题出在两者共享的式 (1) 上，与某个实现细节无关。

### 3.5 排除优化失败、代码写错和配方问题

- **优化失败？** 不是。损失平稳下降，优化本身是成功的。
- **代码写错？** 不是。同一套代码在 SciKnowEval 上复现了原论文的提升，唯一变的是任务难度（这一条有个疑点，见第 6 节）。
- **某个配方特有的问题？** 不是。SDPO 和 OPSD 结果一样。

作者的结论是：剩下的只能是目标函数本身。

### 3.6 换回答长度、题目难度、模型大小，结果也一样

作者逐一排除了几种"也许只是条件不对"的解释（论文第 7 节，表 4、表 5；长度和难度两组用的都是 Qwen3-8B 的 think 模式）：

| 怀疑 | 检验方法 | 结果 |
| --- | --- | --- |
| 解答太长，信号被摊薄了？ | 数学题按回答长度分三档分别训练：短（1318～4364 token）、中（4387～11939）、长（11972～16384） | 三档平均分都低于训练前的 63.4，分别 −1.1、−0.8、−1.6。领域内的 DAPO-Math 每档都小涨（+1.4、+1.0、+0.6），但 9 个迁移测试格子里 8 个下降，剩下 1 个只涨 0.1。监督最不分散的短档也没有明显更好 |
| 题太难，学生根本做不出来？ | MMLU-Pro 按训练前模型 8 次采样的平均正确率分成易（0.75～0.875）、中（0.375～0.625）、难（0.125～0.25）三档分别训练 | 三档都低于训练前平均 60.9，分别 −3.6、−1.4、−1.6，最容易的一档反而掉得最多 |
| 模型太小？ | SDPO 论文报告过自蒸馏的收益随模型变大而增加，于是换 Qwen3-32B 在 MMLU-Pro 上训练 | 起点更高（64.7，8B 是 60.9），训练后 think −0.6、instruct −1.4；训练曲线的特征和 PI 偏差分数都没有减弱 |

再加上两种推理模式（3.3 节）和三种 PI 形式（第 4 节第 1 环），作者认为结论在回答长度、题目难度、模型大小、推理模式和 PI 内容上都没有变。

### 3.7 简单任务上为什么又有效

作者认为，第 4 节的因果链和前人的成功并不矛盾，反而能预测成功出现在哪里。简单任务（比如四选一的科学知识题）有三个特点：

1. 回答短、答案是有限的几个选项，一份参考答案基本就覆盖了"所有正确答案"的范围；
2. 几乎不需要探索，也就没有多少试错可以被罚；
3. 和对错无关的 token 很少。

所以在这类任务上，照着一份答案写，即使 PI 偏差很高，也差不多等于学会做对。回答一变长、答案一开放，这三点同时变弱，"写得像"和"做得对"就分开了。

打个比方（类比是我加的，不是论文原文）：选择题只有 A/B/C/D，抄对了那份答案的选项就算做对；证明题解法很多，照着某一份写不等于会证明。

## 4. 为什么会这样：一条五环的因果链

作者把根源归到两个设计：老师以 PI 为条件，以及逐 token 的密集监督。两者叠加，让损失和"做没做对"脱了钩。

先用一个比方把整条链串起来（类比是我加的，不是论文原文）。学生做一道数学大题，旁边的老师看过某一份标准答案，学生每写一个字，老师就说"标准答案这里会怎么写"：

1. 学生用了另一种同样正确的解法，老师照样把它往那份答案的写法上拽；
2. 学生这道题最后做对还是做错，老师不关心，只看像不像那份答案；
3. 老师纠正最多的是虚词、标点和"等等、也许"这类犹豫词，关键的数字和公式反而纠正得少；
4. 学生试一条岔路再绕回来，老师觉得"答案里没这一步"，罚得最重；
5. 结果学生学会了"写得像"，没学会"做得对"：每一步更没把握，又更早收笔。

```text
老师只认一份答案 → 损失分不清对错 → 力气花在无关紧要的 token 上 → 惩罚试错 → 学生变"钝"
```

下面每一环都是在同一批 Qwen3-8B 训练里实测的（PI 用整份答案）。

### 第 1 环：老师记住的是"那一份答案"

作者设计了 PI 偏差分数，衡量看了 PI 之后，模型续写某段文字的意愿提高了多少。做法是：学生写到第 $`t`$ 个位置时，把一段候选文字 $`w`$ 接在后面，分别问看过答案 $`y^\star`$ 的老师和没看答案的学生"接下来写这段的可能性有多大"。两者平均对数概率之差，就是 PI 把模型往 $`w`$ 推了多少。只需要前向计算，不用训练。

**选读：PI 偏差分数的公式（论文式 (2)）。** 不看也不影响理解。

```math
\mathrm{PS}_t(w)=\frac{1}{K}\sum_{k=1}^{K}\log\frac{p_T(w_k\mid x,y^\star,y_{<t})}{p_S(w_k\mid x,y_{<t})}
```

作者拿四种候选文字来测（论文图 3；图上直接标了数值，这里保留两位小数）：

| 候选文字 $`w`$ | 如果老师懂"对错"，应该… | 实测：数学 / 通用问答 / 编程 |
| --- | --- | --- |
| $`y^\star`$：老师看过的那份答案 | 高 | **0.52 / 0.34 / 0.39** |
| $`y'`$：同一题的另一份正确答案 | 和 $`y^\star`$ 差不多高 | 0.02 / −0.01 / 0.00 |
| $`\tilde y`$：另一道题的正确答案 | 低 | 0.01 / 0.00 / 0.09 |
| $`y^-`$：同一题的错误答案 | 低 | 0.01 / 0.00 / −0.03 |

只有"看过的那一份"分数高。同一道题的另一份正确答案，得分和一道无关题目的答案差不多（编程上甚至更低）。作者的结论是：**老师编码的不是"正确性"，而是那一条具体的解题轨迹**，包括它的用词和步骤顺序。

**换成更模糊的 PI 行不行？** 作者在数学上把整份答案换成提示和技巧卡。偏差确实没了，各候选文字的分数都挤在 0 附近（绝对值都不到 0.06），可老师也几乎不再推动学生，成绩反而更差。论文表 3（数学，Qwen3-8B think 模式，四项测试的平均分，%）：

| PI 形式 | 四项平均（训练前 63.38） | 变化 |
| --- | --- | --- |
| 整份答案 | 63.10 | −0.28 |
| 提示（hint） | 58.25 | −5.13 |
| 技巧卡（skill） | 59.92 | −3.46 |

两头都失败：太具体，老师只会教"照着这一份写"；太模糊，老师什么也教不了。作者据此认为偏差是原因而不只是伴随现象：调节 PI 的具体程度，偏差跟着变，而哪一端都学不到东西。（这组实验有个可能的干扰，见第 6 节。）

### 第 2 环：损失分不清学生做对还是做错

既然老师只认一条轨迹，它就无从判断学生自己的解答有没有做对。如果这个目标真在教人解题，学生做错的地方损失应该更大。实测不是这样（论文图 4a～4c）：

- 做对和做错的解答，平均每 token 的损失都在 3.5×10⁻⁴ 左右，KL 都在 0.03 左右，训练全程两条曲线重叠，做错的 KL 反而略低。
- 两组唯一分得开的指标，方向还是反的：老师和学生的对数概率差距（取绝对值）在前 10 步从约 3 降到 1 以下，之后稳定在**做对的约 0.7、做错的约 0.45**。

也就是说，学习压力最大的地方，恰好是学生已经做对的题。好比一位批改老师，对做对的卷子改得最多，对做错的卷子反而改得少（类比是我加的，不是论文原文）。一个分不清成败的损失可以一直往下降，准确率却纹丝不动，作者认为这就解释了 3.2 节的现象。

### 第 3 环：力气花在不决定答案的 token 上

作者把每个 token 归入 9 类，统计损失落在哪里。论文图 4d（一个有代表性的训练步里，各类 token 占总损失的比例）：

| token 类型 | 占总损失 |
| --- | --- |
| 停用词（the、of 这类虚词）、犹豫词（wait、maybe、perhaps）、标点、空白 | 合计 **55.4%**（27.4% + 11.7% + 14.6% + 1.7%） |
| 实词 | 35.3% |
| 数字、数学符号 | 合计 1.3% |
| 其他、特殊 token | 合计 8.0% |

为了排除"某类 token 数量多所以占比高"，作者又算了每类 token 的平均损失（论文图 5）：犹豫词最高，其次是停用词和实词，数字和特殊 token 最低。犹豫词每个 token 的平均损失大约是数字的 10 倍（读图估计）。

通俗地说：损失有一半以上花在语气和措辞上，比如这里该不该说"等等"、用逗号还是句号；数字和数学符号这些直接决定答案的 token，加起来只分到 1.3%。作者认为这把前人的两个观察统一了起来：OPSD 发现风格类 token 的散度比数学 token 高；Kim 等人发现 SD 对"认知标记词"（表示不确定的词）概率的改动比普通 token 大一个数量级。两者说的都是同一份损失预算被这些低信息量的 token 占了大头，而且训练全程如此，不只是刚开始。

### 第 4 环：试错被当成错误来罚

推理模型在下结论前会先试几条路，所以即使是做对的解答，中间也有一部分合理地偏离了参考答案。看过 $`y^\star`$ 的老师分不出"有用的绕路"和"错误"。

作者在每份解答里，按"学生此刻接着写出 $`y^\star`$ 的可能性"给各个位置排序：前 1/4 叫贴着参考路线（on-path），后 1/4 叫偏离参考路线（off-path）。为了不把"偏离"和"做错"混在一起，先只看做对的解答（论文图 4e；做错解答的数只在正文里）：

| | 偏离参考路线的位置 | 贴着参考路线的位置 |
| --- | --- | --- |
| 做对的解答，KL 最高到 | 约 0.31 | 约 0.08（差 4 倍） |
| 做错的解答，KL 最高到 | 约 0.47 | 约 0.10 |

在学生最后做对的题里，目标函数罚得最重的恰恰是探索，等于把推理必需的搜索当成了错误。作者的解释是，这也是回答变短的原因：模型多想一步就被罚，于是更早下结论。Kim 等人观察到"老师看到的信息越多，学生推理越简短、越自信，在难题上越差"，但没解释原因，作者认为这一环补上了机制。

### 第 5 环：学生变"钝"了，没有变"尖"

老师和学生的平均对数概率差（带正负号）一开始约 3.1，第 15 步左右降到约 −0.65，第 30 步起稳定在 0 附近（论文图 4f）。只看这条曲线，好像学生已经追上了老师。作者用两点说明并非如此：

1. **平均为 0，波动没变小**：±1 个标准差的区间一直在 ±1 左右，没有随均值收窄。这是正负抵消，不是收敛。好比两人逐项打分，这一项你高 1 分，那一项你低 1 分，平均差 0，其实每一项都还差 1 分（类比是我加的，不是论文原文）。
2. **学生更犹豫了**：多数领域里学生的熵在上升，老师对学生解答的困惑度（perplexity）也在上升。如果学生真学会了老师的分布，它应该变得更笃定、更容易被老师预测。

作者的结论：差距缩小不是学会了，而是塌了。学生最后比开始时更"平"，每一步给各个候选 token 的概率更平均，也更早收尾，解出的题却没有变多。这就回到了 3.2 节看到的训练特征：回答变短、验证集持平。

## 5. 作者自己承认的局限

- **只诊断，不开药方。** 这是一项观察性研究：只刻画目标函数的问题，没有提出修复方法。
- **只测了一个模型家族。** 只有 Qwen3 一个家族、两个尺寸（8B 和 32B）、四个领域，作者不对其他架构下结论。
- **有些差距比随机波动还小。** 每个分数是 4 次采样的平均，有些领域里的分数变化比不同次运行之间的波动还小。
- **PI 偏差分数有它的边界。** 它是在采样位置上算的对数概率比，结果依赖另一份正确答案、无关题目的答案和错误答案怎么选。它和 RLSD（一篇从理论上分析这类目标的工作，见第 7 节）的条件互信息分析互补，但并没有真的去估计那个互信息。
- **弱 PI 是另一个模型生成的。** 提示和技巧卡由另一个模型生成，弱 PI 的结果可能部分反映了它们的生成质量。
- **没测和奖励结合的做法。** 保留可验证奖励、只拿老师调整各个 token 权重的做法（比如 RLSD）能不能修好本文的问题，作者明确说他们的实验回答不了，因为没跑这种设置。
- **没说自蒸馏总体无效。** 作者的结论只是：在这些设置里，单独使用以 PI 为条件的逐 token 目标，得不到和任务正确性对齐的学习信号。

## 6. 读的时候值得留意的地方

以下是我读原文时注意到、论文没有重点讨论的点，供参考。

### 证据有多强

- **单个降幅大多不大。** 很多格子的变化在 1～2 分，表里 ± 后面的误差范围却在 1 到 8 分之间，比如 AIME24 是 67.5±7.7 → 66.0±7.8；论文也没说明这个 ± 是标准差还是置信区间。图 2 的验证集曲线看着起伏大，其实纵轴很窄，比如 MMLU-Pro 那条只在约 0.595～0.605 之间（读图估计）。结论的力度主要来自"几乎处处不涨"的一致性，而不是某一处明显的下降。
- **缺少带奖励方法的参照。** 表里只比"训练前"和"只用 SD"，没有在同样四个领域、同样数据上跑 GRPO。Qwen3-8B 的起点已经不低（think 模式 DAPO-Math 79.1%），没有这个正向参照，就分不清"SD 的目标不对"和"这批数据本来就难再提分"各占多少。
- **因果链里只有第一环做了干预。** 换 PI 形式是主动改条件；后面四环都是在同一批训练里的观测统计。比如"惩罚试错导致回答变短"是合理的解释，但没有直接实验验证，例如去掉偏离参考路线位置的损失，看回答还会不会变短。第 5 环说老师的困惑度也在上升，论文只有这一句话，没给图或数字。
- **因果链里唯一的干预实验，提示和技巧卡是以"正确解答"的名义交给老师的。** 附录 D.2 说，提示和技巧卡都是套进 hint 模板交给老师的；数学领域改写过的 hint 模板（清单 11）开头写的是 `Here is the correct solution for the above question:`。提示和技巧卡的实验正好都在数学上做（表 3）。老师被告知"这是正确解答"，看到的却是一两句提示或一张技巧卡，这可能影响弱 PI 的结果，论文没有讨论。
- **复现和难任务用的是不是同一套设置，说法前后对不上。** 论文第 4 节说复现用的是 SDPO 报告的超参数，又说为了在难数据上稳定训练，把 EMA 系数从 SDPO 的 0.01 改成 0.001，并加了激进的逐 token 截断；引言和第 5.2 节却说两边的代码、老师和截断都一样。复现具体用的哪套设置，论文没写清楚，而"排除代码写错"这一条（3.5 节）靠的正是"只换了任务难度"。
- **四条训练特征并非每个领域都齐。** 正文说这套特征在四个领域、两种模式下都一致，但图 2 里工具调用（BFCL）的回答是变长的，从约 1000 变长到约 1400 token；MMLU-Pro 的熵基本持平、略有下降，约 0.42 → 约 0.40（都是读图估计）。从回答长度看，图 2 画的应该是 think 模式（论文说 instruct 模式的 BFCL 回答平均只有约 300 token），instruct 模式的训练曲线论文没给。

### 稿件里的小问题（不影响主要结论）

- **编程领域的平均。** 第 5.2 节说编程领域按测试集和两种模式平均，成绩仍是下降的。但按表 1，think 模式 −0.30、instruct 模式 +0.94，两种模式平均是 +0.32。
- **提示和技巧卡的长度有几种说法。** 技巧卡：第 4 节说约 500 token，附录 A.2 说约 500 词，附录 D.4 的生成提示词要求 250～400 词。提示：第 4 节和附录 A.2 说一到两句，附录 D.3 的生成提示词写的是最多 1～3 句。

## 7. 和相关工作的关系

作者把自己的结果和两篇前人工作放在一起看：

| 工作 | 结论 | 和本文的关系 |
| --- | --- | --- |
| RLSD（Yang 等，2026，[arXiv 2604.03128](https://arxiv.org/abs/2604.03128)） | 从理论上证明 OPSD 的损失里有一项去不掉的条件互信息 $`I(Y_t;R\mid X,Y_{<t})`$：老师拟合的是带 PI 的单条轨迹，不是所有正确解的分布，会把这份"泄漏"教给学生 | 作者认为它只停在理论上；本文的 PI 偏差分数是它在实验上的对应量 |
| Kim 等（2026，[arXiv 2603.24472](https://arxiv.org/abs/2603.24472)） | 老师看到的信息越多，学生推理越简短自信，领域内优化更快，但分布外和更难的题上最多掉约 40%（Qwen3 和 DeepSeek-R1-Distill 系列） | 只描述了现象；本文第 4 节的第 4 环给出了机制 |
| 本文 | 在难任务上单独用 SD 不提升，原因是一条从 PI 偏差到学生变钝的因果链 | 作者认为上面两者是同一个机制的两端 |

**和保留奖励的做法是什么关系。** 作者把这类工作的分工概括为：可验证奖励只管对错，不管写法；SD 项管写法，几乎不管对错。RLSD 的修法是：加减分仍由验证器的对错决定，老师只用来调整各个 token 分到的权重。这样保留了逐 token 的密度，丢掉了带偏差的那一项。这种组合能不能修好本文的问题，作者没有做实验（见第 5 节）。他们的判断是：偏差从第一环（老师只认一条轨迹）就进来了，所以最对症的做法是让密集目标反映"所有正确续写"的集合，而不是只反映一条。

**其他几篇。**

- SDPO（Hübotter 等，2026）和 OPSD（Zhao 等，2026）是本文用的两套配方，它们的做法和原论文报告的结果见第 2 节；作者怎么解释两边结果的差别，见 3.7 节。
- 论文引言在介绍"给自教师看特权信息"这一做法时，引用了 SDFT（Shenfeld 等，2026，[arXiv 2601.19897](https://arxiv.org/abs/2601.19897)）。
- 补充一篇论文没有引用、但结论相近的同期工作：DAPD（Wu 等，2026，[arXiv 2608.01735](https://arxiv.org/abs/2608.01735)）从另一个角度发现，OPSD 会让模型学会"推不出来也硬报一个答案"，训练越久成绩越低。两篇都把问题归到"看过答案的老师"身上，DAPD 还给出了改法，本文只做诊断。

## 8. 总结

这篇论文的结论很直接：**在难任务上，单独用以 PI 为条件的逐 token 自蒸馏，学到的是"写得像那一份答案"，不是"做得对"。** 老师看过一份参考答案，给出的逐 token 目标被那一条轨迹的写法牵着走。学生照着学，损失分不清对错，力气花在虚词、标点和犹豫词上，试错还被罚，最后变得更"平"、更早收笔，解出的题并没有变多。

证据来自很多组设置：四个领域、两种推理模式、两套配方、三种 PI 形式，再加上不同的回答长度、题目难度和 8B、32B 两个尺寸，成绩几乎处处不涨。但单个降幅多在 1～2 分，只测了 Qwen3 一个家族，作者也没有给出修复方法，更没说自蒸馏总体无效。作者给实践者的建议是：SD 的损失下降不能说明模型学到了东西，要看验证集准确率，只有它能分清这两种情况。训练前可以先用 PI 偏差分数筛一遍 PI，成本很低，只需在少量前缀上对四种候选文字做前向计算：老师给"看过的那份答案"的分数如果远高于"另一份正确答案"，说明它传递的是一条轨迹而不是一种能力；四种候选文字的分数都很小，说明这个 PI 什么也传不过去。PI 的具体程度也不是"取个中间值就好"的超参数，整份答案、技巧卡、一两句话的提示都试过，都不行。
