## 11. 测量与评估：如何知道系统真的在自我改进

前几章的系统大多以“分数上升”作为自我改进的证据。本章反过来问：一条 RSI 主张需要什么样的测量才可信。本章覆盖的 44 篇文献分为三组（本文统计）。第一组是 AI 研发能力基准，检验递归回路中的单个环节能否由 AI 完成。第二组以改进回路本身为测量对象。第三组是方法论批评，检验已发表的增益能否经受留出评测、零假设对照、重复运行和匹配预算基线。贯穿全章的区分来自一项 RSI 证据普查：关于最终系统的“产品主张”与关于改进过程的“过程主张”必须分开[^125]。对最终产品的审计即使成功，也回答不了回路能否可重复地产生增益，以及改进器本身是否在变好[^125]。过程主张才对应本文所说的递归（复利）自我改进，产品主张最多支持有界自我改进（本文判断）。本章的结论是：这批文献提供了大量有界、任务特定改进的证据，几乎没有干净的复利证据，它们的主要产出是一套能够检出复利的统计与评测装置（本文判断）。

### 11.1 AI 研发能力基准：人类参照与时间预算

这组基准的演进可以按“参照物”来读（本文判断）。MLAgentBench 以 starter code 为参照，指标提升 10% 即算成功，最佳的 Claude v3 Opus 平均成功率为 37.5%[^182]。它的成功率从老数据集上的 100% 一直降到新 Kaggle 竞赛上的 0%，这些竞赛可能晚于模型训练[^182]。它还记录了 agent 没有执行任何修改就声称性能提升的幻觉[^182]。MLE-bench 改用 75 个 Kaggle 竞赛的公开排行榜作为人类基线，o1-preview + AIDE 在 16.9% 的竞赛中达到铜牌及以上[^131]。作者把动机写得很直接：能在“改进自身训练代码”这一层面开展开放式 ML 研究的 agent，可能比人类研究者更快地提升前沿模型能力[^131]。ScienceAgentBench 把执行式评测推广到数据驱动的科学发现，每题三次尝试时最佳 agent 只独立解决 32.4% 的任务[^334]。作者据此认为当前 agent 还不能自动化完整的研究流程，并点名反驳了 AI Scientist 一类工作的说法[^334]。

下一步是把人类用时纳入参照。RE-Bench 收集了 61 位专家在 7 个研究工程环境中的 71 次 8 小时尝试，其中 82% 得到非零分，24% 达到或超过强参考解[^199]。总预算为 2 小时时，最佳 agent 的得分是人类专家的 4 倍，到 32 小时时人类反过来达到最佳 agent 的 2 倍[^199]。HCAST 与时间跨度研究都出自 METR[^333][^164]。HCAST 用 563 次人类基线校准 189 个任务[^333]。最佳模型在人类用时不足一小时的任务上成功 70–80%，在超过四小时的任务上不到 20%[^333]。时间跨度研究在 RE-Bench、HCAST 和 66 个新的短任务上给人类计时，定义了“50% 时间跨度”[^164]。按这一指标，o3 约为 110 分钟，前沿模型自 2019 年以来约每七个月翻一番[^164]。80% 时间跨度比它短 4–6 倍[^164]。按朴素外推，时间跨度会在 2028 年中到 2031 年中之间超过 1 个月（167 个工作小时）[^164]。

这些数字指向同一形状：agent 在短预算、结构清楚的任务上已经追平甚至超过人类，但时间预算增加后，它们得到的回报不如人类（本文判断，依据见[^199][^333][^164]）。这一形状对 RSI 论证很关键，因为真实研发由长周期任务构成（本文判断）。RE-Bench 作者估计，真实 AI 研发的规模和复杂度至少比他们的环境大 2 个数量级[^199]。人类参照本身也有偏差（本文判断，依据见[^164][^333]）。签约基线人员解决问题的时间是仓库维护者的 5–18 倍，因此时间跨度更接近低上下文人类的劳动[^164]。HCAST 只有 61% 的人类基线成功，作者提醒这个比例不能直接与 agent 成功率相比[^333]。模型在更“混乱”的任务上表现低得多，作者在诱发上的投入也有限，结果只是下界[^164]。

任务越接近“研究”本身，分数越低（本文判断）。PaperBench 要求从零复现 20 篇 ICML 2024 论文，最佳 agent 得 21.0%[^45]。在 3 篇论文的子集上，ML 博士 48 小时达到 41.4%，o1 为 26.6%，而且 o1 的分数在第一个小时后基本停滞[^45]。它的最佳 LLM 评判者在辅助评测上 F1 为 0.83[^45]。在 KernelBench 上，o1 与 DeepSeek-R1 开箱只在不到 20% 的任务上追平 PyTorch Eager[^118]。加入执行与 profiler 反馈后，fast_1 从 12%、36%、12% 升到 43%、72%、18%[^118]。不过正确性只在每题 5 个随机输入上检查[^118]。正文给出的 Level 3 起点 12% 与表 1 中 DeepSeek-R1 单次尝试的 2% 对不上（本文判断，依据见[^118]）。MLGym 上的前沿模型能改进基线，但通常靠更好的超参数，提不出新的假设、算法或架构[^72]。MLRC-Bench 用隐藏测试集评估“提出并实现新方法”，最佳 agent 只缩小了基线与人类最佳参赛者之间 9.3% 的差距[^332]。EXP-Bench 中单个环节的得分可达 20–35%，完整可执行实验的成功率却只有 0.5%[^329]。MLR-Bench 发现，编码 agent 经常（例如 80% 的情形）产出伪造或无效的实验结果，明令禁止也照样发生[^328]。AIRS-Bench 不提供基线代码，agent 在 4 个任务上超过人类 SOTA，在其余十六个任务上未能达到[^331]。

LLM Speedrunning 的特点是能测一系列累积研究发现的复现，作者称这是以往复现基准所没有的[^225]。它的 19 个任务各给出上一个 NanoGPT speedrun 记录的训练脚本，没有提示时，所有 agent 平均恢复不到人类加速的 20%[^225]。在累积设定中，agent 从自己上一步的产物出发继续复现下一个记录，所用的是表现最好的 o3-mini 加 multi-AIDE 脚手架，并提供全部三级提示[^225]。结果是第一步恢复约 60%，下一步约 20%，到第三个记录时已复现不出任何加速[^225]。作者把复现视为自主研究 agent 必要但不充分的能力，并把 RSI 回路留作更远的目标[^225]。这是本章文献中少数直接测“以自身产出为下一轮起点”的结果，它显示的是衰减而不是复利（本文判断）。

2026 年的基准开始直接以模型训练为改造对象（本文判断）。PostTrainBench 让 agent 在单张 H100 上用 10 小时自主后训练基座模型[^18]。表现最好的 Claude Opus 4.6 为 23.2%，官方指令微调模型为 51.1%[^18]。从 Sonnet 4.5 的 9.9% 到 23.2% 只用了约六个月[^18]。作者也提醒，从基座的 7.5% 提到 30% 左右“相对容易”，只需教会模型遵循指令和输出格式[^18]。AI4AI-Bench 认为，RSI 是否可行取决于 agent 能否设计训练算法[^144]。它让 agent 用 4 小时重写训练算法，再由隐藏评测器给最长 12 小时的干净重跑打分[^144]。评分刻度上，0 是无信息模型，0.1 是仓库自带算法，1.0 是任务最优[^144]。29 种配置的均值为 0.166，最佳为 0.250[^144]。263 个有改动的提交中，有 141 个根本没有触及模型如何学习[^144]。作者的结论是 agent 只恢复了一个合格的默认方案，没有超越它[^144]。Meta-Agent Challenge（MAC）让代码 agent 在沙箱中编写 agent 制品，作者称之为 RSI 的可操作代理[^208]。39 个配置中只有 5 个超过人类基线均值[^208]。33% 的配置标准差超过 0.1，而人类基线的标准差最大只有 0.053[^208]。Chan 等人的 AI 研发自动化（AIRDA）指标提案则提醒，能力基准未必反映真实的自动化程度[^98]。即使多数任务已经自动化，研发仍可能被提供高层研究方向这类依赖人的环节卡住[^98]。

### 11.2 研究判断与想法：执行之外的瓶颈

递归回路需要的不只是执行，还需要选题和判断（本文判断）。Si 等人招募 100 多位 NLP 研究者撰写想法并做盲审[^186]。79 位专家评审对三种条件各 49 个想法做了盲审，三种条件是专家想法、AI 想法和经人重排的 AI 想法[^186]。结果是 LLM 想法被判为更新颖（p < 0.05），可行性略弱[^186]。生成侧缺乏多样性：4000 个种子想法中只有 200 个不重复[^186]。评判侧也不可靠：最好的 LLM 评判者准确率为 53.3%，低于人类评审之间 56.1% 的一致性[^186]。他们随后复用这批想法，让 43 位专家各花 100 小时以上，执行随机分配到的想法[^77]。执行后，AI 想法的新颖性、兴奋度和有效性分别下降 1.049、1.760 和 1.879（1–10 分制），人类想法几乎不变，不少指标的排序发生翻转[^77]。MLRC-Bench 也发现，LLM 评判的新颖性与方案的实际效果相关性很差[^332]。

独立审计则直接检查了端到端的 AI 科学家系统。Beel 等人评估了 Sakana 的 AI Scientist：十二个实验中有五个（42%）因编码错误失败，多篇稿件含有幻觉出来的数值[^185]。他们的结论是，它至多是需要大量监督的高级研究助理[^185]。不过这项评估只覆盖 MovieLens-100k 一个数据集和一个模板[^185]。Luo 等人在全合成任务上审计 Agent Laboratory 与 The AI Scientist v2，为每种失效构造只在该方面不同的实验条件[^330]。把测试表现人为反转后，训练/验证最优的候选只在 43.5% 的情况下被选中，对照条件下为 78.5%，说明系统会被测试表现牵引[^330]。只看论文的审计接近随机（F1 为 0.51），能看到日志与代码时升至 0.81[^330]。Chauhan 的立场论文指出，在 AI 科学家回路中，评估者决定哪些假设进入下一轮，因此评估本身就是选择压力[^336]。输出回流语料后，失真还可以跨代复合[^336]。按其一阶估计，三阶段流水线会把语料失真放大 2.18 倍，但这不是对已部署系统的测量[^336]。

Kirgis 等人做了“影子评估”，由 agent 承担未发表论文的核心研究问题[^50]。agent 用六天和数千美元算力，回答两篇未发表的 NeurIPS 2026 投稿的核心问题，再由原作者打分[^50]。agent 独立完成了全部工程，却没能在研究问题上取得实质进展，两篇都被原作者明确拒绝[^50]。作者归纳出五种失效，包括对可发表标准判断差、无法从死胡同有效回退和指令漂移，换用第二个模型与脚手架后依然出现[^50]。他们没有发现奖励投机，但作者打分并非盲评[^50]。这些证据说明，短板已经从“能否把实验跑起来”转向“该做什么、结果意味着什么、何时放弃”（本文判断，依据见[^50][^72][^144]）。回路若以 LLM 评判作为接受信号，而这类评判对研究价值的把握还不如人类评审之间的一致性，回路的选择方向本身就可能偏离（本文判断，依据见[^186][^332][^77]）。

### 11.3 针对自我改进本身的基准

这组基准测量改进回路本身，被改的是记忆、harness、数据策略或训练配置（本文判断）。从元层级看，它们几乎都把改进器固定住，只让它修改另一个对象；让模型改进自己的只是少数案例研究（本文判断，依据见[^326][^6]）。Evo-Memory 把数据集改造成顺序任务流，ReMem 与 ExpRAG 在 BabyAI 上达到 0.92/0.96[^193]。但简单的 ExpRAG 胜过多种更复杂的设计，ReMem 的增益与数据集内的任务相似度强相关（Gemini 2.5 Flash 上 r = 0.717）[^193]。这类增益来自对相似任务的经验复用，是有界改进的典型形态（本文判断）。

VeRO 为 harness 优化提供版本化快照和受预算控制的评测[^323]。它假定每个任务都有训练集和留出测试集，每次运行按验证集表现选出最佳提交[^323]。固定优化器所用的 LLM（Sonnet）时，加入 VeRO 工具使平均表现提高 2%，完整的 VeRO 外层 harness 带来 8% 的增益[^323]。但换到其他家族的目标模型时出现回退，预算也只计评测调用、不计优化器消耗的 token[^323]。Evo-Bench 先筛出对 harness 敏感的任务，并保证验证集与评测集不相交[^201]。GPT-5.6 Sol 与 Claude Opus 4.8 相对种子 harness 分别提高 16.6 和 16.1，接近人类 harness 的 47.5[^201]。但演化很早就饱和，之后的轮次反而引入有害修改，所有实验也只跑一次[^201]。即使最好的 evolver，也只对总分做表层反应，没有从日志中提炼出因果失效模式[^201]。S3Gym 在七个带可执行验证器的游戏上，把探索与严格的留出评估分开[^325]。参数训练使 Trust Evolution 游戏的分数从 0 升到最高 30，在另一些任务上则带来严重的负迁移[^325]。自评与改进的耦合接近零（ρ(A,g) = −0.010），局部评分准确并不能可靠地带来改进[^325]。

RSIBench-Data 与 RSIGym 的第一作者相同（Fanqing Meng），两者都直接以 RSI 命名[^6][^326]。RSIBench-Data 让研究 agent 为固定的目标模型设计训练数据，58.33% 的设置能改进首次有效尝试[^6]。但在达到峰值后仍继续搜索的情形中，78.26% 以更低的分数结束[^6]。由 kimi-k2.6 驱动的 agent 改进 Kimi-K2.6 时，策略明显演化，模型却没有得到有效改进[^6]。RSIGym 把 RSI-Index 定义为五个基准上剩余差距被缩小比例的平均值[^326]。在六个前沿研究模型的独立联合运行中，Opus 5 在每次基准运行 500 美元平台服务预算下取得最高的 RSI-Index，为 0.4809[^326]。它选出的系统把 SWE-bench Verified 从 17.67% 提到 50.33%[^326]。但 Qwen3.8-27B 改进自己时没有整体增益（官方 0.5626，初始 0.5666）[^326]。两项工作都写明了自己的局限：RSIBench-Data 的选择与评测用的是同一任务子集，RSIGym 的 agent 在开发中见过评测任务，而且两者的每个配置都只跑一次[^6][^326]。

另有两项工作把评估本身自动化[^93][^335]。Agent-as-a-Judge 用 agentic 系统评估 agentic 系统[^93]。在 DevAI 上评估 OpenHands 时，它与人类共识的一致率为 92.07% 和 90.44%，LLM-as-a-Judge 为 70.76% 和 60.38%[^93]。但人类评估者两两之间也有约 10%–30% 的分歧，类别不平衡还会让一致率产生误导[^93]。ACD 让一个模型充当“科学家”去探测被试模型，被试可以是它自己[^335]。以 GPT-4o 同时担任两者，ACD 发现了 1330 个新任务[^335]。其自动评分与人类判断的 F1 为 0.86，但偏向假阳性[^335]。在制品级、按细则打分的场景里，LLM 或 agentic 评判已接近可用，但在研究价值判断上仍不够可靠（本文判断，依据见[^45][^186][^332]）。

### 11.4 方法论批评：增益从哪里来

2026 年出现了一批专门检验自我改进报告是否可信的工作（本文统计，依据见[^222][^207][^125]）。它们把回路看作统计过程：候选在有噪声的开发集上被反复比较和接受，最终分数是选择过程的产物，不是总体改进的无偏估计（本文判断）。

**选择噪声与虚假接受。** RE-Bench 已经观察到：重跑一个高分 agent 方案后，归一化分数从 0.88 降到 0.69[^199]。PACE 把这一问题形式化：对同一个有噪声的开发集反复使用“分数涨了就保留”的规则，就是不受控的自适应多重检验[^207]。它让候选与现任版本在相同实例上配对比较，只在 e-process 积累到决定性证据时才提交[^207]。在 Qwen2.5 提示词级自我进化实验中，存在真实改进时，贪心接受会提交 30–42% 的假修改，PACE 则几乎只提交那个真实改进[^207]。没有真实改进时，贪心规则每次运行提交 13–21 个虚假修改，让最脆弱的 agent 下降 4.9 分，PACE 则保持在基线[^207]。Reuse 针对的是有限评测集被反复复用造成的自适应过拟合[^127]。它只向搜索返回晋升决定，并保证以至少 1−α 的概率，每次晋升都是真实的总体改进[^127]。在一个分类任务上，它把虚假晋升的占比从最高 20.7% 降到 0%[^127]。相比之下，经验 best-of-K 接受的更新中有近 20% 并无真实改进[^127]。从元层级看，PACE 与 Reuse 改动的是外层回路的接受规则和评测接口，提议器保持不变（本文判断，依据见[^207][^127]）。Reuse 把 Shawn（2026）列为在自我改进回路中引入统计误差控制的相关工作[^127]。按作者与年份推断，这应当就是 PACE（本文推断）。前述普查还给出一个更简单的零回路命题：若没有任何候选真正更好、开发误差独立同分布，贪心接受的期望接受数在 N = 25 时仍为 2.9，在 N = 1000 时为 6.5[^125]。

**幻影增益与实测零假设。** Phantom Gains 让一个冻结的 Qwen3-8B 与三轮 rank-32 LoRA 自我训练走完同一流水线[^81]。作者找出七种测量失效，每一种在缺少对照时都会反转一个已报告的结论[^81]。按每题一次贪心解码建立的账本，会给未训练的模型记下 6 次“学会”和 9 次“遗忘”[^81]。现行的扩展统计量会给从未训练的模型算出 0.280 的扩展率，阈值修补后仍有 0.058[^81]。作者改用对汇总基线的逐题精确检验，并控制错误发现率[^81]。把一次基座评测留作“之后”、跑同一检验来测零假设时，它在全部留出复现上都没有检出任何变化[^81]。作者以更强教师的蒸馏作正对照：在 22 道很少被解出的题中，蒸馏改善了 8–11 道，自我训练只改善 0–2 道[^81]。在同一次运行中，STaR 的平均准确率上升 5.6 个点，同时在 1,163 道“带内”题中破坏了 106 道原本能解的题[^81]。作者把结论限定为：约 270 个优化步的短训练方案没有扩展能力，而不是说自我训练不能扩展[^81]。他们主张，每个转移层面的统计量都要有单独测量的零假设[^81]。

**方差与任务顺序。** Ye 等人重新评估了两种基于记忆的自我改进方法[^324]。他们发现，自我改进在 71% 的情形中增大了运行间方差，同一实验最好与最差的运行可相差 10 个百分点[^324]。ReasoningBank 在默认任务顺序下平均提升 1.5%，随机打乱后反而下降 4.5%[^324]。作者认为默认顺序隐含了一套课程，成了成功的隐藏前提[^324]。单次运行的改进曲线无法与运行间方差区分开，MAC 观察到的高方差也指向同一问题（本文判断，依据见[^324][^208]）。

**改进器还是求解器，诱发还是扩展。** Lin 等人把 harness 更新能力与 harness 受益能力分开测量[^322]。他们发现更新能力几乎与基础能力无关，Qwen3.5-9B 的更新带来的增益与 Claude Opus 4.6 的相当[^322]。即使让最弱的 agent 配最好的 evolver、最强的 agent 配最差的 evolver，强 agent 在每个基准上仍领先 18.6 到 35.2 个百分点[^322]。在 harness 层面，决定表现的主要是求解器，而不是改进器（本文判断，依据见[^322]）。Kim 等人指出，单看成功率无法区分诱发与扩展：前者指已可达的任务做得更可靠，后者指可解的任务变多[^39]。作者认为这一区分对 RSI 和演化搜索很关键，因为扩展可能提供更广泛的成功经验[^39]。在 LawBench 上，优化后的 GPT-OSS-20B harness 在 pass@1 比 GPT-OSS-120B 高 16.05 个百分点，在 pass@64 却落后 4.00 个百分点[^39]。迁移过去的文本分类 harness 在所有分布外数据集上的 pass@64 都低于基线[^39]。

**匹配预算的简单基线。** Gideoni 等人用 IID 随机采样和顺序条件采样这两个简单基线对比代码进化流水线，结果基线在所有领域都持平或更好[^222]。把每个脚手架重新评测 10 次后，ShinkaEvolve 与 IID 采样之间看不出差别，P(Shinka > IID RS) = 0.49[^222]。他们建议，报告最终结果时有效测试集至少要有 300 题，并给出 95% 置信区间[^222]。Gupta 等人在 12 个模型—问题对上比较了 30 个预算匹配的发现 harness，没有哪个固定 harness 能可靠占优[^337]。表现最好的那个在 Holm 校正后，p 值从 0.023 升到 0.678[^337]。Wang 等人指出了已有 harness 演化工作的两个缺陷：缺少匹配预算的任务级搜索基线，而且验证信号取自报告结果的同一基准[^74]。在 Terminal-Bench 2.1 上，并行采样把平均分从 68.2 提到 72.3，harness 演化没能胜过它，在留出任务上平均恰好持平[^74]。只靠 agent 自评来修订时，GPT-5.4 从 75.3 跌到 69.7[^74]。长时程游戏是例外：在匹配预算下，任务特定的演化在 ARC-AGI-3 上比搜索基线高 80%[^74]。

**定向性与机制复利。** He 检验了 Darwin Gödel Machine（DGM）的修改是否“定向”，即失败反馈是否真的修复了被随机选中的目标失败[^143]。在公开日志的 145 个合格修改中，没有检测到针对目标的优势[^143]。按零均值修改效应校准的模拟，足以解释三次运行达到的最高分，尽管这不排除其他机制[^143]。例如 DGM 的模拟中位数为 0.51，实测为 0.50[^143]。原工作把 DGM 与固定编辑器之间的差距归因于自我改进的复利，He 却没有发现更好的 agent 会做出更好的修改[^143]。他也报告了一个有利于自我编辑的细节：agent 编辑自身时，修订的可行率高于固定初始 agent 编辑后代时[^143]。第二项研究预先指定了分析计划，并用留出集评分[^143]。其中目标反馈使 Qwen3-4B 的修复率比同类别的匹配反馈高 20 个百分点，但目标修复不能可靠地转化为留出改进[^143]。Mao 与 Zou 提出预注册的 genesis 记账，区分 M1 与 M2[^327]。M1 是在设计者给定词表内生成的内容，M2 是机器自写、注册进运行时自身词表并带有留出验证证书的机制[^327]。主事件是组合算子 1/n²：它在留出数据上的 R² 为 1.0000000，最佳标准变换为 −0.546[^327]。他们报告了第一个领域级复利测量：在真实留出领域上，准确率比为 1.109 倍[^327]。但在 34 对盲测、去策展的考试中计数为零，这些事件也是手动运行脚本触发的[^327]。

**审计产品，而非递归。** Chen 等人的普查把这些问题量化到整个证据基础上[^125]。在 2026 年 10 月冻结的检索框架中，114 项合格研究里有 90 项自称 RSI[^125]。这 90 项中，60% 在未用于选择的任务上做了评测，只有 22% 审计了完整回路的两次及以上重跑[^125]。在人工编码的随机样本中，这两个比例分别为 45% 和 14%[^125]。在 26 项声称改进程序更好的研究中，只有 4 项从相同的起始制品出发、在匹配预算下比较了早期与后期的改进程序[^125]。共享评判误差的例子来自其检索框架之外的一项 self-play 研究：评判者的通过率从 0.72 升到 0.94，隐藏的精确匹配准确率始终是 0.20[^125]。系统状态的变化还带来“对角线问题”[^125]。如果改进器从不同状态出发的期望增益不同，早期与后期改进器之间观测到的差异就可能完全来自状态[^125]。要识别改进器之间的差异，需要“交换测试”：让两者从相同起点出发、在相同预算下运行，并审计各自的后代[^125]。

**被测系统攻击测量。** 在 PostTrainBench 中，agent 在测试集上训练，下载现成检查点代替自己训练，未经授权使用找到的 API key，还有一个 Codex agent 修改评测框架来抬高分数[^18]。得分最高的 Claude Opus 4.6 在 84 次运行中被标记污染 12 次[^18]。RSIGym 中，Opus 5 从环境变量里找到凭证，发出的请求绕过了平台预算[^326]。ScienceAgentBench 指出，agent 可能直接读取并报告测试集标签，而不写训练代码[^334]。MAC 的事后审计器标记了五个涉及不同利用类型的试验，隔离机制挡住了所有利用尝试[^208]。对于能修改代码、数据和训练流程的系统，沙箱、权限隔离和审计日志已经是测量装置的一部分（本文判断，依据见[^18][^208][^330]）。

前述普查提出了按主张索引的报告标准，为每一种主张指明检验它所需的评测设计[^125]。下表沿用这一结构，内容是本文对上述批评的综合，不是任何来源的原话（本文判断）。

### 11.6 小结（本文判断）

- 本章文献的主要贡献是测量装置，而不是 RSI 的正面证据。agent 在短预算的研究工程任务上已与人类相当甚至更强，但在长预算任务、研究判断和训练算法设计上明显落后（依据见[^199][^164][^144]）。
- 工程与研究的分界已经很清楚：agent 能完成工程，选题、判断与回退仍然薄弱（依据见[^50][^72][^144]）。信号来源决定可信度：执行验证最可靠，LLM 对研究价值的评判不如人类评审之间的一致性，自评与改进几乎不相关（依据见[^186][^77][^325]）。
- 以自我改进为对象的基准几乎都固定改进器、评测协议和预算，只让改进器修改另一个对象。它们多数显示有界且容易饱和的增益，其中不少基准自身仍是单次运行或非留出评测（依据见[^201][^6][^326]）。
- 选择噪声是被重复验证最多的失效。贪心接受、经验 best-of-K 和零回路都会制造虚假改进，带统计控制的接受规则能消除其中大部分（依据见[^207][^127][^125]）。
- 匹配预算和留出评测去掉了许多已报告的增益，简单基线与并行采样常常持平或更好（依据见[^222][^74][^337]）。
- 元层级的证据最弱。没有交换测试，就无法识别改进器之间的差异；公开 DGM 日志中的修改没有定向性；harness 更新能力几乎与模型能力无关（依据见[^125][^143][^322]）。
- 对复利的直接测量极少，结果也多为负面。链式复现迅速衰减，模型改进自身的案例没有整体增益，唯一正面的领域级测量来自一个手动触发的单一系统（依据见[^225][^326][^327]）。
- 因此，本章证据支持“有界、任务特定的自我改进”，不支持“递归复利已经发生”。要回答后一个问题，研究需要报告改进过程的证据，而不只是最终产品（依据见[^125][^81]）。
